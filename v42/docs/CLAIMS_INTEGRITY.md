# TROLL NFT 2.0 — V42 Claims Integrity

V42 makes honesty enforceable at the product/content layer.

## Rule
Every important product or financial-like statement should be tied to:
- an evidence class;
- an evidence reference;
- wording appropriate to that evidence.

## Evidence classes
- **LIVE_ONCHAIN_BALANCE** — exact chain/contract state observed live.
- **REGULATED_ENTITLEMENT** — separately recorded regulated entitlement.
- **HISTORICAL_PROOF** — verified prior proof, not necessarily current balance.
- **REFERENCE_ONLY** — family/theme/affinity or non-financial reference.

## Claims automatically rejected
- guaranteed return/profit/appreciation/yield;
- risk-free claims;
- saying a family/theme directly owns underlying shares;
- claiming Robinhood endorsement/sponsorship/approval without evidence;
- categorical promises that NFT price will rise.

## Product UI
The same rules should govern:
- Passport;
- collection dashboard;
- marketplace copy;
- grant submissions;
- social/marketing copy generated from project data;
- agent responses.

## Why
The product can become more valuable by becoming more useful, secure, transparent and verifiable. The software should not require exaggerated claims to explain that utility.

## Security boundary
V42 is validation/content tooling only. No Solidity, signing, custody or transactions.
